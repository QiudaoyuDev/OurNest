## 职责

承载微信小程序的页面、共享组件和客户端状态，完成账本与记录的交互、展示和同步。

## 边界

页面和组件通过服务层访问云端业务；服务层封装请求、状态和缓存，不拥有服务端权限裁决。通用视觉和交互遵循 `ui-guidelines`，缓存隔离与刷新遵循 `cache-policy`。

## 新增记账入口与分类

- Tabbar、首页、明细空态和创建账本后的新增入口直接打开 `record-edit` 新增模式；支出/收入及现有分类树在同页选择，分类管理为次级入口。
- 新增模式初始分类为空，不从默认名称或路由元数据隐式选中分类；切换收支类型清空分类但保留金额、日期、备注、账户等输入。金额有效且明确选择分类后才能保存，提交前再次校验。
- 分类树按稳定分类 ID 呈现唯一选中态，不按名称匹配；使用浅底、边框与勾选共同表达，顶部分类信息与树内状态一致。分类标题保持单行，管理入口按内容宽度显示，不改变公共按钮默认布局。
- 分类读取与管理返回后的同步复用 category service/store；刷新后已删除的分类清空，分类加载失败可重试，加载中或失败时不可新增提交。
- 新增时数字键盘常驻底部，大面积完成键计算表达式并直接保存，成功后返回；编辑模式保留原有分类重选、保存和删除操作。键盘负责底部安全区，保存仍由云端确认并判定权限。
- 新建、编辑及连续记账成功不发送成功文字 Toast，以返回或表单重置表达完成，避免重复打断操作；等待云端确认期间保留保存中状态并阻止重复提交，失败保留输入并提示。连续记账仅清空金额、备注和标签等本笔内容，保留分类、账户、日期及账本上下文；删除反馈不受此规则影响。

## 支出占比分类明细

- 月度与年度占比的真实扇区、分类行使用相同的稳定分类身份选中，展示最近 3 笔支出及完整明细入口；同名分类不共用选择身份，界面显示父分类以区分。图表内部名称与显示名称分离，避免绘图库按显示名合并选中状态；选择只派发图表 action，不重建图表。
- “其余分类”是合并扇区，不是名为“其他”的真实分类。点击后使用公共 Bottom Sheet 列出实际省略的分类，再按所选 ID 或 legacy 父子名称身份查询；选中隐藏分类时高亮其所属合并扇区，不将合并金额作为该分类金额。
- 预览通过 record service 调用现有 `record/list`，固定支出类型及当前账本、服务端半开日期范围和分类过滤，首屏 3 条；金额和笔数来自完整 `rangeSummary` / `rangeRecordCount`，不从预览求和。完整明细使用同一过滤，不新增云接口或持久化预览。
- 预览只读，状态互斥为 Loading → Error / Empty / Ready；错误可重试，选择切换立即清空上一分类内容。请求序号与查看上下文共同隔离旧响应，切换分类、账本、周期、图表、记录更新和卸载后不得写回过期结果。
- 分析与明细是独立云查询；预览总额与所选分类金额按分不符时进入需刷新分析的错误状态，不显示不一致明细或开放旧过滤入口。完整明细继续由服务端判定权限，预览不提供行内写操作。

## 趋势明细下钻

趋势点击按真实时间桶生成明细范围；最高、最低标记携带稳定桶标识，不使用标记自身序号定位日期。普通数据点仅接受有效整数索引，未知组件事件、缺失桶及无效日期不导航。范围保持起含止不含，并截断至服务端返回的周期结束边界。零值日期仍参与最低值，并列最值选择首个桶；零支出日的空明细不改变最低值定义。
