# 分析页数据处理与图形渲染：全流程优化实施方案

> 状态：待实施；本文件是实施计划，不代表功能已完成或已通过真机验收。
>
> 目标：一个完整工程周期内，闭环解决显示正确性、刷新一致性、小数据等待和大数据扩展问题。分步开发、逐步验证、统一验收，不把所有改动混成一次高风险提交。
>
> 边界：本轮编写方案，不修改业务代码、不操作云环境、不迁移用户数据。当前事实仍以相关 SPEC 与 `docs/` 为准；实施涉及的契约变更必须与代码、全部调用方和测试在同一交付单元更新。

## 1. 成功标准与范围冻结

### 1.1 必须交付

- 自定义、周、月、年、累计之间切换，图表、日期、金额和空状态正确；不以补零掩盖缺失字段。
- Tab 隐藏、显示、页面进入后台和返回、写入及共享账本同步，均有明确的失效和恢复闭环。
- 图表实例的创建、更新、事件绑定、尺寸恢复和销毁由统一入口管理；同一有效节点不重复初始化。
- 一次逻辑变更不因事件和版本同步重复触发相同分析请求；请求进行中遇到新的真实变更不得被误合并丢失。
- 每次业务请求不再承担集合创建操作；分析减少冗余扫描，明细后续页不重复读取全部统计元数据。
- 建立可重放的交互测试、真实云端对账、性能测量和发布回滚记录。
- 本轮必须完成查询投影、单次分桶及 ECharts 包体评估；聚合、预计算和跨页面缓存按第 10 节的门槛明确选择“实施”或“有证据不启用”，不能保持待研究状态。

### 1.2 不做的事情

- 不调整品牌、全局颜色、卡片、navbar、图标体系和收支统计口径。
- 不实现成员退出、Owner 转移、邀请生命周期等未确定产品规则。
- 不增加离线写入、客户端权限判断或由前端上报身份决定服务端授权。
- 不为本轮引入 CI 平台、监控平台、消息队列、Redis 或灰度基础设施；沿用本地检查、云日志和微信测试环境。
- 不把生产账号或真实账单用于压测，不使用生产 `resetDatabase`，不提交密钥、用户数据或运行日志。

### 1.3 “一次性完成”的定义

一次性完成设计、实现、跨端验证、性能收敛和发布准备；不是承诺任何规模下永久无需优化。所有已知风险必须有实现、验收证据或明确的范围结论，禁止用“以后再看”结项。若出现基础设施或权限阻塞，标记阻塞并停止发布，不用本地模拟替代真实验收。

## 2. 诊断事实与不确定性

### 2.1 已确认

1. Tab 保活后仅通过隐藏切换，但分析组件仍订阅记录变更；隐藏期间可能请求并重建 Canvas，激活没有配套恢复入口。
2. 次级图表调用 `canvas.setChart(chart)`，未像主图一样向 `ec-canvas` 包装组件绑定实例，触摸事件无法转发。
3. Canvas 零尺寸初始化仅有限重试，失败后依赖外部重新触发；不能靠继续增加延时解决可见性问题。
4. 自定义切回月/年使用当前日期，不沿用自定义日期；不存在“空 anchor 必然导致 Invalid Date”的证据。
5. 年度 `analysisView: true` 跳过五年记录查询，却仍生成 `recentYearTrend`，导致该字段伪零；新年度主图并不依赖它。
6. 路由包装每次等待六次集合创建尝试；写入事件与后续版本同步存在重复刷新路径。
7. 月度分析读取六个月完整记录，普通分析可持续翻页读取全部范围；明细每页重复读取范围统计和历史元数据。
8. 月/年顶部柱图是 WXML/CSS；分类环图和自定义趋势使用 ECharts，必须分开验证。

主要代码入口：

- `miniprogram/pages/index/index.{js,wxml,wxss}`
- `miniprogram/components/tl-tab-analysis/`
- `miniprogram/components/ec-canvas/`
- `miniprogram/services/{record.service,ledger.service,ledger.store,data-sync.service,api}.js`
- `cloudfunctions/ourNest/index.js`
- `cloudfunctions/ourNest/shared/helpers.js`
- `cloudfunctions/ourNest/handlers/{analysis,record,dashboard}.handler.js`
- `cloudfunctions/ourNest/analysis.helpers.js`

### 2.2 尚未确认，必须在首阶段取证

- 用户现场的空图究竟是顶部柱图、分类环图，还是整个分析页进入错误状态。
- 故障响应是否缺少 `dashboard`、`daily`、`recentMonths`，及小程序与云函数部署是否匹配。
- 日历是服务端没有金额、所选类型或周期不符，还是最终文字渲染不可见。
- 冷启动、集合管理调用、索引、数据库、网络和渲染各占多少耗时。

此前 86 项相关测试通过；内存验证能生成支出 `8.50`、收入 `25.00` 的日历格。桌面仅 dashboard 计算和 view-model 转换约为 50/500/5000 条的 0.18/0.84/8.42 ms，不含云端、传输、完整 handler 和微信渲染，不能作为端到端性能结论。

## 3. 默认设计决策

为减少实施过程反复讨论，本方案固定以下默认值；如需改变，必须在编码前一次性记录差异，而非开发中暗改。

1. **保留 Tab 实例，但显示状态显式传入。** 各业务组件接收 `active`；页面 `onHide/onShow` 另行传入前台状态。实际可工作条件为两者同时满足。不能把组件保活误当作原生 page lifecycle 会自动覆盖自定义 Tab。
2. **保留现有时间切换语义。** 自定义切回月/年仍回当前周期；测试必须核对标题与请求范围。若以后决定沿用自定义结束日期，作为独立产品变更，不混入性能修复。
3. **日历继续按所选收支类型显示。** 零金额和未来日期仍显示 `—`；真实金额使用分累计，完整精度用于明细与对账。
4. **默认不新增跨页面结果缓存、不持久化统计。** 只保留页面实例状态和短生命周期进行中请求合并。离开分析再返回时校验并重新读取，隐藏时不提前读取分析。
5. **默认不新建日/月汇总集合。** 先去掉固定开销、重复查询，完成投影和单次分桶；达到第 10 节门槛才增加持久化衍生数据。
6. **旧/新 Canvas 不同时盲目切换。** 本轮先统一注册与恢复，保留现有兼容策略；2D 迁移按跨端证据决定，不直接移除历史兼容开关。
7. **保留当前公开分析字段的真实语义。** 不以空数组补出虚假的五年零值；如果未来移除字段，必须单独同步契约和调用方，不能私下停算。
8. **不静默截断。** 任何上限必须明确返回错误；不得把部分范围统计包装成完整总额。

## 5. S0：证据、测量与测试数据

### 5.1 先复现原始症状

使用独立测试账本，记录以下操作和结果：

1. 有历史收支的自定义区间 → 当前月 → 当前年；标题、请求参数、响应范围均保存到脱敏测试记录。
2. 当前周期分别设置为无记录、仅收入、仅支出、混合收支，区分正常零值与加载失败。
3. 分析 → 明细 → 新增/编辑/删除 → 返回分析；隐藏时间覆盖请求完成前、完成后两种情况。
4. 分析 → 我的 → 另一账号修改共享账本 → 手动同步 → 返回分析。
5. 日历选定一天，逐层核对 `dashboard.daily`、`dashboardView.cells.amountText`、最终节点文字与尺寸。
6. 点击真实环图扇区，而非只点击分类列表；核对预览请求与类别身份。

每次记录环境别名、小程序与云函数版本、微信基础库、OS、设备、网络类型、操作序列和错误。禁止记录完整 OpenID、备注、账单原文和令牌。

### 5.2 分段观测

复用已有云端 `durationMs`，增加受开发/测试开关控制的结构化阶段测量，不接入新平台：

- 客户端：逻辑操作 ID、请求 ID、刷新来源、上下文摘要、请求开始/结束、响应字节数、setData 字节数与回调耗时。
- 图表：节点世代、可见性、尺寸、初始化/更新/销毁次数、初始化失败类型、选项提交到首帧完成的耗时。
- 云端：授权、集合准备、各查询分支、页数、读取条数、分类及用户补充查询、聚合/内存处理、序列化前载荷大小、总耗时。
- SDK 无法报告扫描量或执行计划时，不伪造数值；记录可获取的操作数、返回条数及单查询耗时，并附控制台索引状态。
- 不用客户端减服务端绝对时间戳计算网络耗时；两侧分别测量持续时间，通过请求 ID 关联。
- 测量开关默认关闭；常态保留现有成功/错误日志，扩展错误信息不包含业务明细。测试日志只在受控本地或云控制台保存。

### 5.3 数据集

通过测试环境专用生成工具准备合成数据，执行前显式核对环境和账本 ID；禁止工具接受 production 环境。工具应可幂等生成、按本次测试标识清理，清理不得按模糊账本名称删除。

必须覆盖：

- 条数边界：0、1、30、50、99、100、101、500、1000、5000、20000 条。
- 分布：单日集中、跨六个月、跨五年、同日期大量记录、空月份、闰日、跨年周、月末同期。
- 金额：0.01、0.1/0.2、千元/万元、整数/小数、并列最高值；只使用当前业务允许的有效有限金额。
- 分类：同名不同 ID、legacy 同名不同父级、改名历史、无效图标、超过 20 个和超过 100 个类别。
- 账户：空账户与实际名称“未设置账户”并存。
- 身份：个人账本、共享 Owner、普通成员、只读访客、已失去访问权限。
- 变更：并发新增/编辑/删除、跨账本移动若当前支持、批量导入、分类迁移、多端共享更新。

样本生成、预期金额和截图 fixture 必须由同一组基础记录派生；至少保留少量人工手算用例作为独立 oracle，避免“同一函数同时算预期和实际”的假通过。

## 6. S1：页面状态与刷新协调器

### 6.1 状态划分

业务状态互斥为 `loading → error / empty / ready`；图表状态独立为 `idle / waitingVisible / initializing / ready / error / disposed`。

每个业务组件维护：

- `active`、`foreground`、`attached`。
- `dirty`、`invalidationGeneration`、`requestGeneration`、`sessionGeneration`。
- 当前上下文、进行中请求、最新待请求上下文、已展示的云端版本（若可验证）。

上下文包含：环境、账号会话世代、账本 ID、mode、标准化 anchor/自定义日期、analysisType。图表类型只在影响服务端结果时进入查询键；纯本地换图不得重新查询。

事件处理规则：

- 首次进入：激活后查询一次，未激活组件不 bootstrap 业务查询。
- 变为隐藏：立即使旧 UI 回写失效，取消可取消的计时器/测量；网络不支持取消时忽略返回，不谎称已取消云调用。
- 隐藏时收到变更：只设置 dirty，不取数、不初始化 Canvas。
- 再次激活：按最新上下文重新读取一次；同一激活事件与同步结果合并。
- 可见时收到变更：使当前快照及下钻失效，调度刷新；同一上下文只允许一条活跃请求。
- 请求期间上下文变化：仅保留最后一个待请求上下文，拒绝旧响应回写；失败不得清除新 dirty。
- 请求期间发生新的数据变更：本次响应不视为覆盖该变更，结束后至多启动一次追赶请求；有持续真实写入时可连续追赶，不为满足“只发一次”牺牲一致性。
- 退出/账号环境切换/账本被移除：清空页面快照、下钻及图表，旧 Promise 不得跨会话回写。

所有异步回调都校验 attached、会话、上下文、请求/图表世代；不仅校验分析主请求。

### 6.2 统一写入与同步通知

新增轻量的客户端刷新协调模块，建议放在 `miniprogram/services/data-refresh.service.js`，职责是合并失效通知，而不是保存分析结果。

- `record.service` 写成功后立即发出一次统一失效，带实际账本 ID、客户端逻辑 mutation ID；服务端返回可验证版本时一并携带。
- 编辑/删除不能依赖客户端可选的 `payload.ledgerId` 推断范围；实际账本 ID 由服务端授权后的返回值提供，服务端不得信任客户端身份参数。
- 保留写后版本同步，但对同一 mutation 的同步回声去重；同一同步结果在首页、明细、分析上使用一致规则。
- 不简单忽略所有后续 sync：版本高于当前已覆盖版本、其他设备写入、分类迁移和权限变化必须再次失效。
- 自动同步未变化不刷新业务；手动同步成功即使版本未变，也显式使已访问业务视图失效，隐藏视图下次激活再查询。
- 手动同步仍须等账号、账本、当前分类全部成功后才提示成功；失败不更新成功时间。不能因 `notify: false` 吞掉最终业务失效。
- 删除/失去账本权限首先清除旧数据，再决定回退账本，不能继续展示无权访问的旧金额。
- 一次导入分批写入可产生多个真实版本：UI 在隐藏时聚合为一次激活刷新；可见时合并进行中的失效，最后一批结束后必须追赶到最新版本。

版本是性能和一致性辅助，不是权限凭证。业务变化与 revision 必须原子提交；“最终递增成功”不足以证明读快照稳定。现有删除路径先 remove、再单独 bumpLedgerSyncRevision，存在业务已变而版本未变的窗口，且 bump 失败可被吞掉。W3 必须将删除等普通写入与版本递增纳入同一事务，并在事务内重新读取记录、账本、权限及冲突版本。分批迁移等流程须原子设置进行中标记、逐批递增版本，分析读取遇到未稳定状态明确拒绝或重试。任何影响统计、图标或权限的写路径未完成此审计与修复，均不得启用稳定快照声明、版本跳过或结果缓存。

### 6.3 Loading 与保留图表节点的冲突处理

现有外层 `wx:if="loading"` 会移除 Ready 分支，因此只改 `renderChart()` 不会实现实例复用。

实施必须一起调整组件结构：

- 状态占位与图表宿主分层；同一模式、同一节点的短暂刷新可保留宿主，但 Loading 时隐藏整个旧 Ready 内容、禁止交互，不能提前展示旧金额。
- 隐藏宿主时不做尺寸测量、init 或 setOption；数据校验并进入 Ready、宿主恢复布局后再统一更新。
- 如果模式变化确实替换 WXML 节点，则销毁对应实例，创建新世代；不可给已销毁 Canvas 派发更新。
- 初次加载、Error、Empty、无账本和失权清除路径按状态机处理，不强行创建空图。
- 若目标微信运行时无法稳定保留节点，优先正确性：只在该明确边界重建，并记录原因；不能在报告中宣称已完成普遍复用。

## 7. S1：图表注册、数据契约和日历闭环

### 7.1 图表统一注册表

建议新增 `miniprogram/components/tl-tab-analysis/chart-controller.js`；主图和次级图不得各自维护不一致生命周期。

每个图表键保存宿主组件、Canvas、实例、节点世代、上下文世代、尺寸、事件解绑器和渲染状态。

1. 仅在 active、foreground、Ready、节点存在且宽高大于零时初始化。
2. init 后同时执行 Canvas 与包装组件的实例绑定；主图、dashboardCategory 和累计分类图使用同一流程。
3. 同节点更新使用 `setOption`；配置明确替换 series，避免旧系列残留；分类选择只用 `dispatchAction`。
4. 尺寸变化使用 `resize`，重测量只在激活、模式布局变化、设备尺寸变化时发生，不在每次滚动都尝试重建。
5. 节点替换、卸载、会话失效或无权限时，解绑事件、dispose、包装层 `setChart(null)`、清空重试与注册表。
6. 零尺寸进入 waitingVisible，等待明确激活和布局完成；可在 nextTick 后有限重测，不循环固定延时直到“碰巧成功”。可见且有效节点仍失败时进入图表 Error，业务列表可继续展示。
7. 失败恢复使用同一 controller 入口，区分主图/次级图，不只修改一个布尔标志。
8. 每个旧回调校验节点世代，防止自定义旧 Canvas 的延迟事件注册成月度新图。
9. 滚动分区测量设置时间节流和单飞，导航测量保留最新目标；卸载与隐藏后回调不得更新状态。

触摸绑定和 ECharts 库版本不一起升级；先锁定现有版本复现与修复，再评估裁剪或2D迁移。

### 7.2 响应校验

建议在 `miniprogram/services/` 增加分析响应校验器，先验证原始响应，再运行 `decorate()`，不能被默认空数组掩盖字段缺失。

周/月/年 `analysisView: true` 至少验证：

- 账本身份匹配；mode 和范围有效，日期为半开区间且与所请求周期一致。
- `overview` 和 `dashboard` 存在，金额为有限数值，笔数为非负整数，`dashboard.type` 与请求一致。
- `daily`、分类、账户、排行字段存在且为数组；合法空数组与缺失必须区分。
- 月度 `recentMonths` 恰好六个连续且唯一的月份；年度 `trend` 包含截止范围内应有的月份桶；未来展示补齐在 view-model 完成，不伪造历史金额。
- 周度本期和上期趋势桶日期与对应范围一致。
- 年度 `recentYearTrend` 恰好五年且金额来自真实记录，未来所选年遵守现有返回规则。
- 分类稳定 key 不重复；每日日期不重复、金额单位为元，累计和对账按分计算。

一致性断言：所选类型的 daily 合计、分类本期合计、账户合计与 dashboard.total 到分相等；笔数与有效排行范围一致。排行最多五笔，不要求排行金额合计等于全部总额。补零桶可以存在，但不能替代缺失聚合字段。

缺字段、非法日期、NaN、错误类型和不守恒进入明确契约错误；显示公共错误态并可重试，日志保留错误码和字段路径，不记录账单内容。服务端业务错误与图表错误分开，不能都归成“网络问题”。

### 7.3 日历验证

- 从真实 records 计算 dashboard.daily，再转换为 cells；同时用手算 oracle 验证。
- 在 320/375/390/430 宽度检查最终文字、金额省略、今天/选中/未来样式。
- 有金额日期不得显示 `—`；若仅另一收支类型有金额，当前类型显示 `—` 属于正确行为。
- 点击日期后的完整合计按当前类型和半开日期范围查询，金额保持精度；翻页不改变合计。
- 异步修改导致日历汇总与明细不同，提示刷新并重新读取，不继续展示已知不一致的明细。

### 7.4 年度五年趋势

先恢复真实契约，再优化：一次查询覆盖所选年往前四年至本期结束的联合范围，从中派生本期、上期和五年趋势；历史年结束边界和当前年截至今天分开处理。分桶只做一次；不要恢复成三个重叠全量扫描。

五年趋势的数据范围扩大应纳入 S2/S3 大数据测量；若达到读取预算门槛，使用真实聚合结果，不以移除字段或补零规避开销。

## 8. S2：云端初始化、查询和分页

### 8.1 将集合准备移出请求热路径

- 新增独立部署前工具，例如 `scripts/prepare-cloud-environment.mjs`，使用显式环境参数及项目既有授权方式，不在仓库保存凭据。
- 集合清单从代码实际使用情况枚举，不能只复制当前六个集合；一并核对导入、反馈、操作日志等路径需要的集合。
- 幂等创建缺少的集合；已存在不报错，真正的权限/配置错误必须失败，不广泛吞掉。
- 该工具不自动设置宽松安全规则、不删除集合、不读取账单；安全规则和索引独立核验。
- 移除路由 `wrap()` 中每请求 `ensureCollections()`；正常业务处理不尝试后台补建。
- 缺集合时返回可诊断配置错误，不自动切换环境或绕过权限。
- 发布前预检证明所有路由所需集合可用，测试“新环境未准备”应明确失败。

本轮选择部署期准备，不再引入每实例首次业务请求的初始化等待；如当前部署权限不支持，作为 S2 阻塞项处理。

### 8.2 查询范围与并发预算

- 权限读取必须最先完成；未授权不发 records 查询。
- 周/自定义本期与上期读取独立，授权后可并行，两条 records 分支为默认并发上限。
- 月度一次查询六个月联合范围，单次按月份/日期/分类分桶得到本期、上期和六个月汇总。
- 年度按第 7.4 节联合范围派生，不重复读取相同记录。
- 成员和分类补充查询在输入 ID 已确定后并行；单一补充维度的批处理并发上限为二，不对每个成员单独发请求。
- 游标分页仍按稳定日期和 ID 顺序；不得用客户端自行拼接未授权数据库查询。
- 不因并行读取丢失版本一致性：查询开始与结束重新读取/核对账本同步版本；不同则本次不作为稳定快照发布，受控重试一次，仍变化返回明确可重试状态，禁止无限重试。
- 版本围栏只适用于所有相关业务变化与 revision 原子提交的前提；S0 必须逐路由审计新增、编辑、删除、导入、分类修复/迁移、账本与权限更新，W3 修复不满足的路径。仅将 bump 错误改为抛出、重试或最终补偿不能消除窗口；前提未满足时不得发布带稳定快照保证的接口。
- 分批操作的开始标记和结束确认与版本更新同事务提交；读围栏同时校验进行中标记。不得在非稳定批次中返回混合结果，即使两次读取的 revision 恰好一致。

### 8.3 明细元数据分级契约

沿用 `record/list` 路由和 `{ route, payload }` 协议，新增明确可选参数 `metadataMode`：

- `full`：默认；返回分页、全账本历史数量、最新日期、范围笔数及金额，适用于明细首屏。
- `range`：返回分页、范围笔数和金额，不查全账本数量/最新日期，适用于分类、账户和日历首屏下钻。
- `none`：只返回分页、权限、账本及版本信息，适用于后续页；没有计算的元数据返回 `null` 或按最终契约省略，所有客户端必须明确处理，不能 `|| 0` 覆盖首屏统计。

分页分支和需要的统计分支授权后并行；用户资料只为实际返回页查询。每次请求都重新鉴权，`none` 不是免鉴权通道。

增加 `snapshotRevision` 响应和可选 `expectedRevision` 请求：

- 首屏在稳定版本围栏下返回汇总和版本；客户端保存该页面快照。
- 后续页带该版本；若期间发生变更，返回 `RECORD_SNAPSHOT_CHANGED`，清空分页并从首屏刷新，不拼接两个版本。
- 服务端在请求结束前再次核对版本，避免查询途中变更仍返回旧版本标签。
- 不在本轮改变现有 `{ date, id }` 游标形状、默认 30/最大 50 或服务端游标验证。
- 首屏后续页的统计只来自首屏完整范围；不以已加载记录求和。

实施时全量搜索 `listRecords`/`record/list` 调用方，至少覆盖首页若有调用、明细、record-filtered、分类预览、ratio-preview、日历、访客路径和测试 mock。`full` 默认用于仍存在的已发布客户端调用，不保留旧 action 协议或新建重复分页接口。

## 9. S2：计算、传输与索引

### 9.1 字段投影和单次分桶

- 由统计维度明确字段集：记录 ID、日期、类型、金额、categoryId/name/parent/icon、账户、录入人、familyAttribution，以及真实 Top5 需要的备注等字段。
- 不能因投影漏掉家庭归属、legacy 分类身份、历史图标候选或预览信息；字段清单用契约测试保护。
- 只保留 Top5 需要的记录字段；对全部记录不做不必要复制和反复排序。
- 一次遍历构建日/月/年、收支分类、账户、录入/付款/消费、计数及 Top5；按分累计，最终统一转元。
- 小集合最终排序保留稳定 tie-breaker；Top5 可使用有界结构，不要求引入复杂依赖。
- 旧 helper 在结果逐分相等且所有调用方迁移后删除，不长期维护两套正式计算事实来源。
- 本期为空仍计算真实上期，不丢失上期对比。

### 9.2 精简前端数据桥

- 原始响应、ECharts option、Map 和索引保存在组件私有字段，不整体展开进 `this.data`。
- `this.data` 只保存 WXML 实际读取的视图字段及明确状态；选中、下钻和列表更新使用局部 patch。
- 同一完成阶段只做一次主要 Ready patch；模式纯展示切换不重复装饰整个响应。
- 分离当前模式不需要的 legacy 展示派生结果；不得误删服务端仍承诺的响应字段。
- Loading 后的回调也校验世代，防止旧 setData 回调重画新上下文。

### 9.3 目标环境索引核验

以实际 query 和排序为依据，在 test 环境逐条执行、记录状态；下列是候选而非已部署事实：

- 分析升序游标：`ledgerId ASC, date ASC, _id ASC`。
- 明细：既有 `ledgerId ASC, date DESC, createdAt DESC, _id DESC`。
- 最近记录：既有 `ledgerId ASC, createdAt DESC`，同时核对具体路由实际排序。
- 类型/分类：按 `ledgerId, type, categoryId, date, createdAt, _id` 的具体过滤与排序评估；legacy 父子名称筛选独立验证。
- 账户、familyFilter OR 分支按真实查询评估，不能机械建立所有字段排列组合。
- 分类与用户补充查询按实际 `ledgerId + _id in`、`openid in` 方式核对。

索引记录包含环境别名、集合、键与方向、构建完成状态、对应请求、数据量、查询次数/耗时、错误或 SDK 限制。既有唯一索引不得改弱。生产分别预建并验收；不要在请求中自动建索引。

## 10. S3：增长策略的确定性决策

### 10.1 数据库聚合

S2 后，出现下列任一情况即进入本轮数据库聚合实现，不推迟到下次：

- 5000 条范围的查询与传输占端到端暖请求耗时超过 60%，且第 12 节目标未达标。
- 年度五年/累计读取随记录数近线性增长，20000 条无法在预算内完成。
- records 读取页数或返回字节数成为云函数内存、响应限制、超时风险，且索引和投影已经正确。

默认先用在线数据库聚合计算日/月/年、类型和账户；需要稳定分类身份的聚合明确区分 ID 与 legacy，不能按显示名合并。排行通过限定查询，历史图标与家庭归属补充按最小必要读取实现。

必须在 CloudBase 上验证逐条分转换表达式、空账户、日期桶、排序 tie-breaker 和 SDK group/limit 行为；聚合结果不能默认无上限。分页 group 超限时完整读取或显式报错，禁止截断。原始记录 oracle 与新结果在全部合成集到分相等才允许切换。

### 10.2 日/月预计算，仅在在线聚合仍不达标时启用

只有在线聚合仍不满足增长档目标、且瓶颈明确时才实施；否则本轮结论固定为“不启用，在线计算通过验收”。

如启用，必须同时交付以下完整闭环，不接受只新增一个 totals 集合：

1. 按账本、日期和稳定维度键存储整数分及笔数，明确 schemaVersion 和 generation；原始 records 仍为事实来源。
2. 新增、编辑、删除、导入、分类迁移均更新或标记受影响旧/新日期与分类；不能只覆盖新增。
3. 事务容量内的记录与汇总写入共同提交；超容量场景采用标记→分批重建→校验→完成确认，持久化进度，幂等可恢复。
4. 重建期间按账本版本前后围栏验证一致；写入导致版本变化时重建受影响范围或重试，不把不完整代次设为 active。
5. 批次 token/版本保证重复执行不重复加钱；负差额、删除最后一笔、跨日编辑均有测试。
6. 无可用汇总代次、版本不匹配或校验失败时明确回退在线精确统计，不能展示过期汇总。
7. 客户端不能直接访问汇总集合；每次接口仍以原账本鉴权。
8. 测试环境备份、全量回填、并发演练、断点续跑、总额对账、切换与禁用回滚必须全部完成。
9. 更新数据库、写安全和云函数 SPEC；上线前单独审查新增写放大与事务争用成本。

不得直接向生产执行本地迁移；生产回填需独立批准、备份和恢复演练。

### 10.3 ECharts 裁剪与加载策略

本轮先建立依赖清单，使用实际启用的 line/bar/pie、tooltip、grid、legend、markPoint、renderer 和交互生成可复现构建；组件引用不等于运行时未使用，必须搜索 chart-options 和事件依赖。

- 优先裁剪当前锁定版本而非同时升级库；保留许可证、版本及构建命令/依赖锁。
- 目标是实际绘图库文件至少减少 30%，同时不增加首屏启动成本；达不到则记录原因及实测，不能伪报优化。
- 裁剪会破坏兼容时，评估微信合法分包/异步组件能力、基础库和跨包引用限制；不能照搬浏览器动态 import。
- 裁剪已满足启动与切换目标时不再叠加复杂分包；若分包，首次分析额外下载与失败重试必须计入测量。
- Canvas 后端切换单独验证旧 canvas、2D、滚动层级、裁切、触摸、DPR 和 iOS/Android；保留兼容结论。
- 环图选择不重建实例；普通数据刷新如动画使交互超过目标，减少该次更新动画而非全局改变视觉规范。

### 10.4 统计缓存

默认不开启。仅当同一上下文重复读取占比高、前述优化仍未满足目标，且所有写入/权限失效可证明时，才启用会话内有界结果缓存。不能借缓存掩盖云端慢查询。

如启用，固定规则：

- key 至少包含环境、账号会话世代、账本、服务端 revision、mode、完整日期范围、analysisType、响应 schema 版本；当前未结束周期另含业务当天，跨日失效。
- 有界 LRU，最多 10 个上下文、总计 1 MiB、最长 60 秒，三者任一达到即淘汰；不写本地持久化。
- 命中前仍需有效的服务端权限及版本校验，不能凭本地版本继续展示已撤权金额；校验失败清空，不展示旧结果。
- 本地写入、共享版本更新、分类变更、手动同步、删除/失权、退出和环境切换全部失效；并发旧请求不得重新填入。
- in-flight 合并与已完成结果缓存分开实现；不把失败 Promise 留在缓存。
- 同一交付更新 `docs/CACHE-POLICY.md`、客户端 SPEC 和回归断言；没有审批和契约更新不得偷偷启用。

如果额外权限/版本校验抵消收益，本轮明确不启用。缓存收益用同网络 A/B 重复上下文场景验证，而不是只报命中函数运行时间。

- fixture 按请求的 mode、anchor、类型生成正确响应，不再固定返回月度支出数据。
- record/ledger/category/sync 所有服务调用都使用完整 stub；未登记的 `wx.cloud.callFunction` 直接失败，防止脚本误访问真实环境。
- fixture 可控制延时、失败顺序、缺字段和版本变化；图表仍使用真实包装层、ECharts 与微信布局。
- 等待明确状态、节点及图表事件，不以固定 sleep 代替成功断言；设置总超时防挂死。
- 先断言金额、坐标、状态及请求计数，再做截图；不能仅看截图像不像。
- 缺分析视觉基线必须报错；人工确认后一次性建立，不能为通过检查自动更新基线。
- 脚本清理临时项目、连接和服务；失败保留脱敏诊断路径，不改当前开发项目和云环境。

强制交互场景：

1. custom→month→year→custom，包含当前/历史区间及有数据/无数据。
2. 请求未完成连续切换 mode/ledger/type，最终只显示最后一个上下文。
3. 隐藏→写入事件→等待完成→激活，隐藏期零请求/初始化、激活一次刷新。
4. 隐藏前请求迟到、隐藏期间多次变更、请求中再次写入，最终追赶正确。
5. Canvas 初次零尺寸→显示后有效尺寸，成功恢复且没有重复实例。
6. 环图真实扇区触摸、分类折叠和“其余分类”；dispose 后点击无副作用。
7. 日历文字实际出现、长金额不挤压、翻页合计不变。
8. 手动同步 unchanged/changed、另一账号更新、失权、退出重登和环境变化。

开发者工具模拟不能替代真机原生 Canvas 触摸和层级测试。

### 11.3 真云端与真机

- CloudBase：真实 SDK 分页、整数分聚合、分类/账户/family 过滤、索引和事务并发。
- 两账号：Owner/成员互改、访客只读、撤销访问后的清除；不自行实现未决退出规则。
- iOS 与 Android 各至少一台实体设备，至少一台中低性能设备；记录机型、OS、微信和基础库。
- 320/375/390/430 宽度用工具补齐；实体设备以实际尺寸记录，不能冒充拥有所有尺寸的真机。
- 正常网络与受控弱网分别记录，冷/暖启动分别统计。

## 12. 性能目标与查询预算

以下是本轮拟定的发布目标，不是已达到的性能。S0 固定设备、测试环境、网络和数据分布后记录基线；不得为通过验收在实现完成后调低标准。确因微信或云基础设施不可控需调整时，须附分段证据并在发布前批准。

### 12.1 采样方式

- 每个核心模式/数据档至少 30 次暖请求，记录 P50/P95/最大值；冷启动另外采样至少 10 次，不与暖请求混算。
- 端到端从用户操作到正确内容与图表可交互；数据 Ready 与图表完成分别计时。
- 至少 100 次混合模式/账本/类型切换，统计空白、错账、重复实例和未处理异常；另进行 200 次循环检查存活实例数量。
- 网络差异、冷启动状态和其他后台操作写入报告，不删除慢样本来美化 P95。

### 12.2 发布目标

- 0–100 条小数据、正常网络、暖请求：端到端 P95 ≤ 1500 ms；云 handler P95 ≤ 700 ms。
- 101–1000 条同条件：端到端 P95 ≤ 2000 ms；云 handler P95 ≤ 1000 ms。
- 5000 条查询范围：端到端 P95 ≤ 3000 ms；云 handler P95 ≤ 2000 ms。
- 20000 条增长场景：完整精确统计端到端 P95 ≤ 5000 ms；不超时、不截断、不使用旧版本结果。
- 小数据新链路端到端 P95 相对 S0 至少降低 30%；如果旧基线已 ≤ 1000 ms，可按绝对目标验收并披露改善幅度。
- 响应完成后，视图更新和图表可交互的 P95 ≤ 400 ms；不将预设动画完成时间与实际阻塞混为一谈。
- 单次主要 setData 目标 ≤ 50 KiB，硬性要求远低于平台单次限制；达不到时提供按字段体积归因并消除不需要的重复数据。
- 弱网允许请求更慢，但 Loading 应在下一次视图更新呈现，失败可重试、保留选择、不会闪出旧 Ready 内容；不以正常网络阈值判弱网失败。

### 12.3 行为与操作数硬约束

- 正常业务请求 `createCollection` 次数为 0。
- 隐藏分析组件主动分析请求和图表初始化次数为 0。
- 同上下文单飞；一次没有并发外部写入的保存，当前可见分析最终只请求一次；变化发生在请求中时允许一次必要追赶，并记录原因。
- sync unchanged 自动检查不触发分析；手动同步与激活的重复失效合并。
- 同节点纯数据更新 init 次数为 0、setOption 为 1；切换节点先 dispose 再 init，存活实例数始终等于实际需要的图表数。
- `metadataMode: range` 不查全账本 count/latest；`none` 不查 count/aggregate/latest，仍执行授权、版本围栏、游标验证、分页和必要用户补充。
- 月/年重复扫描归零；读取次数随真正页数增长，不因六个月/五个年份再扫描六次/五次。
- 不为减少查询数移除授权和快照围栏；操作预算应区分必要的安全一致性查询与冗余统计查询。

## 13. 文件级工作包与并行边界

### W0：复现与契约

- 范围：测试数据生成规则、性能报告模板、响应契约草案和本计划执行记录。
- 先冻结 active、刷新事件、metadataMode、revision、图表 controller 接口。

- 输出：active/foreground、统一失效、手动同步、写后回声去重、会话隔离。

- 范围：`ourNest/index.js`、`shared/helpers.js`、analysis/record/dashboard handlers、analysis helpers、环境准备工具。

- 范围：`tests/`、视觉/交互/性能 scripts、`package.json`、ECharts 可复现构建。

- 输出：文档同步、全套测试、独立代码审查、CloudBase 对账、双端性能报告及回滚演练。

可并行 W1/W2/W3 的独立文件与 W4 测试，W0 必须先完成，W5 串行收敛。文件重叠由指定归属者合并，不采用多个代理同时编辑相同文件再靠覆盖解决。

## 14. 发布、回滚与最终完成定义

### 14.1 文档同步

实施时同步更新：

- `miniprogram/SPEC.md`：active/dirty、图表 lifecycle、请求和下钻失效边界。
- `cloudfunctions/ourNest/SPEC.md`：部署前准备、查询及版本围栏边界。
- `docs/DATABASE.md`：实际分析字段、五年趋势、metadataMode/snapshotRevision/expectedRevision、集合准备和索引事实；不得保留“每请求按需建集合”的旧描述。
- `docs/CACHE-POLICY.md`：页面保活、隐藏失效、激活读取、通知合并；只有启用结果缓存才写缓存新规则。
- `docs/WRITE-SAFETY.md`：如修复版本递增或启用预计算，补齐一致性与恢复约束。
- `docs/REGRESSION.md`：本计划新增交互、分页、真云端和性能步骤。
- `README.md` / `docs/CLOUD-ENVIRONMENTS.md`：新增实际可执行命令、部署顺序及环境预检。
- `plan/PENDING.md`：作为唯一待办入口链接本计划；完成项由 Git 保留，不复制多套未完成清单。

### 14.2 部署顺序

1. 冻结当前小程序和云函数制品，保存版本、依赖锁、环境配置、索引和安全规则备份。
2. 在测试环境执行集合准备、索引建立并等待完成，再部署云函数。
3. 核对旧客户端调用默认 `full` 的返回契约；新客户端遇旧云端必须明确报契约错误，不能静默变零。
4. 在测试环境部署配套客户端，完成全量回归、性能和弱网/双账号验收。
5. 如触发预计算，先完成测试回填及恢复；生产变更需独立批准和备份，不因本计划默认授权。
6. 生产先准备集合和索引、部署兼容现有客户端的云函数，再上传配套小程序；发布前确认 production.id、同名 ourNest 和配置隔离。
7. 发布后在批准的账号和最小数据范围内做冒烟，观察错误率、耗时、重复请求与契约错误；不在生产压测。

### 14.3 回滚

- 触发：错金额、跨账本/账号数据、失权数据残留、数据丢失、统计截断、持续空图、无法登录/写入，立即停止发布或回滚；明显性能回退先按分段数据定位，无法及时消除则回滚。
- 小程序有审核和发布时延，不能假设瞬间撤回：优先恢复已验证兼容当前已发布客户端的云函数，暂停新客户端推进。
- 不先把云函数回滚成新客户端不识别的旧契约；保留必要的新增可选读参数/响应，使默认调用和已发布新版本都能工作。
- 默认方案不改原始记录结构，回滚不需要删除或恢复用户账目；索引先保留，确认无依赖后再清理。
- 如启用汇总/缓存，先禁用衍生读路径并回退精确在线统计；保留原始记录及重建进度，禁止清库掩盖错误。
- 数据恢复只能使用同环境已验证备份和明确批准的范围；生产不得导入测试环境快照。
- 回滚后执行登录、权限、收支 CRUD、分页、分析/日历和共享同步最小回归，记录结果及版本。
