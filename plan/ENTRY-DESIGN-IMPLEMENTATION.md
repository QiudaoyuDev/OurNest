# 记一笔界面实施方案

## 目标与边界

依据 `outputs/entry-detail-project-design.html` 优化分类选择后的录入界面；保留暖红体系、分类先行、记账权限及云端契约。保留已有工作区修改；不部署、上传或修改云数据。

## 实施步骤

1. 在现有面板内明确分类、金额、备注、日期和账户：金额独立突出；备注有标题与输入框；日期、账户以带标题和箭头的控件显示。沿用类型切换与分类选择，重选不丢输入。
2. 共享支出显示付款人、消费归属及个人消费时的消费成员；共享收入显示收入归属。保留加载、失败重试、校验和保存边界。
3. 调整键盘及快捷金额的触控尺寸，保留加减、计算、两个保存动作和底部安全区。面板超出屏幕时滚动；备注输入时隐藏自定义键盘。
4. 收支编辑移除标签输入及删除入口，仅有历史标签时只读展示。编辑保存旧记录时原样保留标签；模板导入和云端字段不变。
5. 更新相关说明和回归测试，覆盖分类、家庭归属、连续记账、历史标签及失败状态。运行单元测试、UI、静态和云函数检查、完整 verify，按条件尝试视觉检查。

## 验收与风险

- 新增默认无分类，必须手动选分类；切换收支清空分类但保留输入。
- 金额无中文单位；完整数值和运算结果可读，数据和运算规则不变。
- 历史标签在只读和编辑明细可见，编辑保存不清空或改写；不删除历史数据。
- 分别检查个人和共享账本、加载与失败、长名称、小屏滚动和备注键盘。
- 本地检查不能证明开发者工具、真机、云环境和正式发布；视觉自动化不可用时记录待验证项。
- 回滚仅限本次新增与修改内容，保留原有未提交改动，不整体重置工作区。
