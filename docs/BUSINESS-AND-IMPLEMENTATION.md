# 当前业务与代码实现

本文以当前仓库源码为依据，描述实际业务与边界，不作为云端、真机或正式发布证明。

## 产品闭环

1. 用户通过微信云身份登录，维护昵称和头像。
2. 创建个人或共享账本，或通过邀请码预览并确认加入。
3. 选定账本后手工记账或导入文件，查看首页、明细和分析。
4. Owner 设置预算、管理成员及账本；成员参与记账，访客只读。
5. 本机写入主动刷新，其他参与者通过前台版本检查或手动同步获知变化。

## 账本与角色

个人账本允许 Owner 写入并可邀请只读访客；共享账本支持 Owner、成员与访客。服务端角色为 `owner`、`member`、`readonly`，成员治理参数中的访客值为 `visitor`，不要混淆。

| 操作                               | Owner                  | 成员       | 只读访客 |
| ---------------------------------- | ---------------------- | ---------- | -------- |
| 读取账本、记录、统计、成员         | 是                     | 是         | 是       |
| 新增记录、导入                     | 是                     | 是         | 否       |
| 修改/删除记录                      | 全部                   | 仅自己录入 | 否       |
| 新建分类                           | 是                     | 是         | 否       |
| 编辑/删除分类                      | 是，排除受保护其他分类 | 否         | 否       |
| 配置支付账户、快捷金额             | 是                     | 是         | 否       |
| 修改账本资料、预算、邀请和成员治理 | 是                     | 否         | 否       |
| 退出                               | 否，先转移或删除       | 是         | 是       |

退出、移除或角色变化不改写历史记录的录入人。共享账本所有权转移由现有成员确认后完成，原 Owner 成为成员；双方可取消待处理申请。转移递增 `ownerEpoch`，阻止旧邀请在所有权转回后恢复有效。

## 记录与分类

- 金额以元存储，服务端要求大于 0、不超过 99,999,999 且最多两位小数；聚合以分计算。类型为收入或支出，日期使用有效的 `YYYY-MM-DD`。
- 分类当前为按收支区分的扁平列表。名称同账本同类型去重，长度最多 6 个字符；`isOther` 分类不可修改删除，普通系统默认分类不受此保护。
- 记录保留分类名称/图标快照，稳定 `categoryId` 用于关联和统计；旧父分类字段只承担历史兼容，不提供新的层级编辑能力。
- 删除分类将引用该 ID 的记录迁移至同收支类型的其他分类，不按旧名称猜测历史归属。
- 支付账户仅是名称；最多 12 个，名称最多 12 个字符。快捷金额可开启并保存 1–5 个值。

## 家庭视角

`ownerOpenid` 表示录入人；共享支出的 `familyAttribution` 单独表示付款人与消费归属。消费归属可以为个人、公共、多人或未知，公共/多人不会自动均摊。分析页差额提示仅比较前两名付款人并取差额的一半，不是多人通用结算，也不执行转账。

手工新记录有当前用户默认值，导入和缺失字段的历史记录按未知处理，不将录入人自动解释为付款人。服务端限制新选择的付款/个人消费成员来自当前账本 Owner 或成员；访客不能成为新指定对象。

## 查询与统计

首页由云端返回当月汇总和跨期最近记录，不能拿最近记录求和当月总额。明细采用稳定游标，统计来自完整查询范围，不从已加载页拼出全量统计。后续页携带版本时可检测快照变化，收到 `RECORD_SNAPSHOT_CHANGED` 应重新加载首屏。

分析由云端聚合，支持周期、趋势、收支分类和账户等维度；当前周期对比同期，历史周期对比完整上期。预算只表示当前配置。客户端校验分析上下文和金额契约，不用虚构零值掩盖错误。

云端另提供 `ledger/analysis/compare`，最多比较 12 个月或 5 年、最多读取 5000 条；目前前端服务没有对应封装，不能仅凭接口存在宣传已有完整多期比较入口。部分统计查询有容量保护，实际性能和索引仍需测试环境验证。

## 导入闭环

上传凭证 → 云存储文件 → 预览解析 → 选行/人工确认 → 分批提交 → 完成摘要及文件清理。

- 支持模板以及有可识别表头的微信支付/支付宝 CSV、XLSX；预览最多 5 MB、200 行。
- 失败/关闭交易不能导入；退款、转账、还款等特殊交易需人工确认方向，来源分类不自动映射。
- 来源交易号仅在可靠时参与确定去重；日期、金额相同只提供疑似重复提示，不应盲目丢弃。
- 每个事务最多写入 10 行，记录、批次进度与账本版本同时提交；重试只处理未完成行。
- 文件引用和清理状态保存于操作集合；未开始批次可取消，已开始批次需继续处理。中断、文件清理失败和孤儿文件不是同一种状态。

详见 [数据契约](./DATABASE.md) 与 [恢复策略](./WRITE-SAFETY.md)。

## 当前边界与待验证事项

- 导出仅有占位提示，没有导出实现；没有离线写入、云端推送、自动结算或银行连接。
- 分类旧层级数据仍可能存在，未据此承诺自动完成历史迁移。
- 仓库提供本地模拟测试和视觉检查脚本，但不提供本轮真机、生产索引、安全规则或备份恢复成功证据。
- 成员治理、邀请和分类的协作约束见 [自动化协作规则](../AGENTS.md)；实际权限与事务行为以云函数为准。
