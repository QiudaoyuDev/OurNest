## 聚合、预计算与缓存决策（本地）

- **在线数据库聚合：不启用。** 尚无 CloudBase 测试环境的 5,000/20,000 条端到端数据、索引和 SDK `group` 行为测量，无法证明第 10.1 节的触发阈值；现有范围读取、投影、单次分桶和分页元数据分级保持精确统计。
- **日/月预计算：不启用。** 它依赖在线聚合仍未达标的实测证据，并要求回填、可恢复重建、写入双写和测试环境演练；这些前置条件均未满足，不能以本地基准代替。
- **分析结果缓存：不启用。** `docs/CACHE-POLICY.md` 已规定分析每次读取云端；本轮仅保留页面实例、失效合并和进行中请求协调，未保存完成结果。未取得同网络重复上下文的 A/B 数据前，不引入会掩盖权限或 revision 问题的缓存。
- **重新决策门槛：** 在隔离测试环境完成 5,000 与 20,000 条数据的索引、响应字节、查询页数及端到端 P50/P95 测量后，按计划第 10 节判断是否实现在线聚合；只有在线聚合仍未达标才评估预计算或会话缓存。

## ECharts 包体评估（本地）

- 当前 `miniprogram/components/ec-canvas/echarts.js` 为 986,444 bytes 的 ECharts 5.1.0 微信 Canvas 适配产物；分析页仅使用 `pie`、`bar`、`line` 系列。
- 上游同版本 `echarts.simple.min.js` 为 469,345 bytes，理论上可减少约 517 KB；但它不是现有微信 Canvas 适配构建，直接替换后在当前非浏览器加载探针中访问未定义的 `document`，不能据此宣称小程序可用。
- **结论：本轮不替换包体。** 保留已验证的适配产物，避免以未经真机图表初始化、触摸和视觉回归验证的通用浏览器构建换取体积。待获得 `TL_WECHAT_CLI` 与真机基线后，使用同版本的可复现微信 Canvas 裁剪构建重新评估；若通过所有图表类型和交互回归，再以实际包体差额替换。
