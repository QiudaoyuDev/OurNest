# 缓存与同步规则

## 数据来源

账目与统计以云端为准。首页读取 `ledger/dashboard/get`，明细读取 `record/list`；整段范围金额和笔数使用 `rangeSummary`、`rangeRecordCount`，不能用已加载分页求和替代。分析从 `ledger/analysis/get` 请求，不提供持久离线统计副本。

## 缓存范围

| 内容           | 存放与隔离                                                     | 更新规则                                                             |
| -------------- | -------------------------------------------------------------- | -------------------------------------------------------------------- |
| 登录资料       | `ourNestAuth`，用户/OpenID/环境 key                            | 登录更新，退出或环境 key 变化清理                                    |
| 账本列表与配置 | `ourNestLedgerCache`，环境 key + OpenID                        | 保存版本及 `lastSyncedAt`，前台约 2 分钟检查                         |
| 分类           | `ourNestCategoryCache`，环境 key + OpenID                      | 2 分钟有效期，冷启动、过期或失效等待查询，不是过期立即返回再后台更新 |
| 记录和统计     | 页面实例及运行内状态                                           | 范围/账本切换、写成功、版本变化后重查                                |
| 导入恢复与清理 | 本地批次 ID、选行、人工确认和待清理标识，环境 ID + 用户 + 账本 | 继续批次、完成或清理重试时维护；不存完整账单文件                     |

不能将本地存储概括为只有三个键。没有离线写入队列；保存和删除需要云端确认。缓存、登录进行中请求及旧响应受会话代际保护，不能替代云端授权。

## 更新闭环

1. 记录写入成功先失效视图并发出变更事件，再强制检查账本版本。写成功而同步失败应单独提示，不误报写失败。
2. 刷新协调器在微任务中合并同范围事件，并使用 `mutationId` 去重。可见面板刷新，未打开面板进入后请求。
3. 自动检查仅在前台运行，后台停计时。版本变更使相关分类失效，账本移除时清除其分类。
4. 手动同步串行执行强制登录、账本同步、所有分类失效、当前分类刷新、记录完整同步时间并通知刷新。不预读全部分页记录，任一步失败不提示完整成功。
5. 个人页“账本上次检查”读取账本 Store 的 `lastSyncedAt`，可以来自持久缓存，不只代表本次手动同步。运行内 `dataSyncedAt` 才表示完整手动同步成功时间。

## 隔离边界

退出清理登录、账本、分类缓存，旧请求返回不得跨会话写回。环境隔离主要使用环境 **key**；同 key 下更换实际环境 ID 不保证触发自动清理，应显式退出并清理缓存验证。导入恢复采用独立隔离键，不应宣称退出或环境变化必定清除所有导入恢复信息。
