# OurNest 首页、明细与分析体验综合评估

> 审查基线：当前工作区，HEAD `6063a468a853350e8e02f0f10136c760d82e3e19`；工作区有既存未提交修改，不能视为该提交或线上版本。方法：源码与项目规范静态审查，结合三个独立专项报告和 mini-program-engineering-suite 的证据分级。未运行小程序、云环境、真机、读屏或故障注入；视觉和用户影响均为待验证推断。本报告不修改业务代码。

## 01 执行摘要

**方向：保留温暖可信的账本体系，以财务口径和交互可恢复性优先于视觉重做。** 首页回答“本月怎样”，明细回答“发生了什么”，分析回答“为什么及如何比较”；目前三者已有基本闭环、状态组件与部分图表文字替代，但静态审查发现财务文案可能与数据口径不符、刷新或分页失败缺少清晰恢复，以及只读入口与角色不匹配。建议先修语义与状态，再做结构和视觉精修，不建议先全局换肤或添加装饰性图形。

| 优先级 | 核心事项                         | 证据性质                           | 预期结果                               |
| ------ | -------------------------------- | ---------------------------------- | -------------------------------------- |
| P1     | 分析二次失败提示和重试           | 静态条件可推导，待复现             | 无空白、可恢复、数据与筛选上下文一致   |
| P1     | 生活月报周期及收支口径           | 固定文案与动态数据绑定，待组合验证 | 展示和复制的标题、周期、方向一致       |
| P1     | AA 提示的适用前提                | 计算及措辞可见，实际数据待核实     | 明示估算前提，不暗示真实债务或自动结算 |
| P1     | 访客空态写入口                   | 模板与拦截代码直接可见             | 无不可执行写入口，服务端校验保留       |
| P2     | 两种明细分页失败恢复             | 错误分支静态可见，待断网验证       | 保留已有记录，尾部可重试               |
| P2     | 无障碍、趋势替代与密度           | 静态风险，需设备实测               | 操作有名称和状态，图文可互相验证       |
| P2     | 公共按钮、预算信息重复与金额约数 | 代码事实及设计建议                 | 一致组件、减少重复、避免近似数误读     |

## 02 业务约束与评估边界

- 产品为个人/共享账本。Owner 可管理全部记录，成员只可编辑删除自己录入的记录，访客只读；客户端的显示控制不是服务端授权替代。依据：[业务与实现](../BUSINESS-AND-IMPLEMENTATION.md#L25-L38)。
- 首页当月汇总与跨期最近记录是不同数据集；明细分页的月汇总来自完整查询范围；不能用当前已加载页算整体。分析当前周期对比同期，历史周期对比完整上期，预算仅为当前配置。[统计口径](../BUSINESS-AND-IMPLEMENTATION.md#L56-L62)。
- 付款人、消费归属、录入人不同；公共/多人不自动均摊。差额不是多人通用结算，不应承诺自动转账。[家庭视角](../BUSINESS-AND-IMPLEMENTATION.md#L50-L54)。账户只是名称而非余额；无离线写入、实时推送或已实现导出。[产品说明](../../README.md#L22-L30)、[边界](../BUSINESS-AND-IMPLEMENTATION.md#L76-L80)。
- 延续 `#F0442F`、浅暖背景、现有 navbar/卡片、本地线性图标；除 tabbar 外不加阴影；沿用公共组件和安全区规则。加载、错误、空、就绪互斥。[UI 规范](../UI-GUIDELINES.md#L3-L17)。
- 审查含首页、明细列表、记录详情、分析及筛选下钻。四个 Tab 是同一主页面内面板，不是四个独立原生页面。[页面容器](../../miniprogram/pages/index/index.wxml#L9-L31)。

## 03 首页：先让预算与本月账况易读

**现状与保留**：有无账本、加载、错误、空态，预算和本月收支、跨期最近记录；“最近记录”不应被用户理解为当月汇总来源。[首页模板](../../miniprogram/components/tl-tab-home/index.wxml#L1-L205)、[状态映射](../../miniprogram/components/tl-tab-home/index.js#L33-L39)。

1. **P1 只读空态**：空态“记一笔”未按只读隐藏，点击才被拦截。[模板](../../miniprogram/components/tl-tab-home/index.wxml#L37-L41)、[处理器](../../miniprogram/components/tl-tab-home/index.js#L452-L456)。建议只读时显示中性说明和可执行浏览操作；保留客户端拦截及云端授权。验证空账本及本月空记录两种情形。
2. **P2 预算表达**：预算状态和右侧均可能呈现“已使用”比例。[模板](../../miniprogram/components/tl-tab-home/index.wxml#L42-L74)。建议将余额/超支作为主信息，比例保留一次，预算未设置、零预算、超支分别有清楚文案；不假设历史预算归档存在。
3. **P2 数字精度**：大于等于 100000 的首页汇总用一位小数的“万”表示。[格式化](../../miniprogram/components/tl-tab-home/index.js#L17-L20)。建议舍入时明确“约”，并提供精确金额查看路径，覆盖正负与边界；不要将账户名称描述为账户余额。
4. **版式方向**：保留暖色与卡片，将账本身份、账期、预算/收支、最近记录排成明确层级。长账本名、超大金额、窄屏和系统大字需实际检查，静态代码不能证明拥挤或合规。

## 04 明细与记录详情：连续浏览和角色可预期

**现状与保留**：按月、收支筛选和日期分组；分页采用游标、快照变化自动重新加载；详情将金额、交易信息、家庭信息分组。[列表模板](../../miniprogram/components/tl-tab-records/index.wxml#L1-L100)、[分页](../../miniprogram/components/tl-tab-records/index.js#L238-L310)、[详情](../../miniprogram/pages/record-detail/index.wxml#L12-L80)。主明细对只读者打开详情，其他用户进入编辑页；这不等于成员可编辑他人记录，最终权限仍需服务端与编辑页检查。[入口](../../miniprogram/components/tl-tab-records/index.js#L435-L439)。

1. **P1 只读空态**：列表空态始终有“记一笔”，处理器对访客 toast 后返回。[模板](../../miniprogram/components/tl-tab-records/index.wxml#L88-L94)、[处理器](../../miniprogram/components/tl-tab-records/index.js#L414-L421)。建议访客隐藏写操作，区分筛选无结果、本月空、有历史与无历史，提供合理可执行操作。
2. **P2 追加失败**：主明细追加失败只结束加载，筛选明细追加失败则整体切换错误态。[主明细](../../miniprogram/components/tl-tab-records/index.js#L292-L317)、[下钻](../../miniprogram/pages/record-filtered/index.js#L125-L145)、[模板](../../miniprogram/pages/record-filtered/index.wxml#L7-L25)。建议首屏错误与分页错误分开；追加失败保留内容和游标、尾部重试；快照冲突另行说明并重新加载首屏。
3. **P2 组件一致性**：明细重试和空态按钮用私有 `view`，建议替换为公共 `tl-button`，检查大小、反馈和读屏，避免页面私有通用按钮。[模板](../../miniprogram/components/tl-tab-records/index.wxml#L46-L50)、[规范](../UI-GUIDELINES.md#L5-L8)。
4. **详情设计原则**：保留带正负号的金额、来源、账户、录入人与家庭归属；缺失信息使用准确的“未指定/未知”，不得把录入人当作付款人。核验长交易号、长备注和历史成员，不把当前只读详情页面误述为已有编辑按钮。[字段映射](../../miniprogram/pages/record-detail/index.js#L19-L72)。

## 05 分析：先保证结论可信，再优化图表阅读

**现状与保留**：周期、收支切换、概览、趋势、分类列表和家庭视角已有实现；分类有名称、金额、占比及图表失败备用列表，值得保留。[分析模板](../../miniprogram/components/tl-tab-analysis/index.wxml#L71-L185)、[分类](../../miniprogram/components/tl-tab-analysis/index.wxml#L242-L275)。

1. **P1 二次失败恢复**：错误占位依赖 `error && !chartFirstReadyEver`，后续请求失败置错误并清数据，正文在错误时隐藏，静态推导首次成功后的失败可能没有错误入口。[模板](../../miniprogram/components/tl-tab-analysis/index.wxml#L59-L69)、[逻辑](../../miniprogram/components/tl-tab-analysis/index.js#L970-L1014)、[样式](../../miniprogram/components/tl-tab-analysis/index.wxss#L37-L48)。应确保所有失败均有解释及重试，若保留旧数据必须明确旧账本/区间；先注入失败确认实际效果。
2. **P1 月报语义**：周/月/年及收支切换下仍有“生活月报”，弹层固定“家庭总支出”但绑定当前方向总额，复制也固定写家庭支出。[入口](../../miniprogram/components/tl-tab-analysis/index.wxml#L71-L83)、[弹层](../../miniprogram/components/tl-tab-analysis/index.wxml#L596-L610)、[复制](../../miniprogram/components/tl-tab-analysis/index.js#L1091-L1115)。建议产品二选一：严格限于月度支出，或以统一语义模型动态生成周期、收支、账本语境，并共享给展示与复制。覆盖周/月/年 × 收入/支出 × 个人/共享。
3. **P1 AA 口径**：前两名付款人的差额除二，但文案有“需转账”“结清”表述。[计算及复制](../../miniprogram/components/tl-tab-analysis/dashboard.js#L84-L132)。这不是一般债务计算；建议产品确认仅在能证明两人、共同费用、等额分摊等前提时展示金额，否则说明不可推算；即使适用也标注假设和排除项，不承诺自动结算。先核实服务端数据组成及实际场景。
4. **P2 图表与可访问性**：周对照图有两组柱，但展开文本未列对应上周逐日值；部分图表标签字号小且分类颜色哈希可能碰撞。[趋势](../../miniprogram/components/tl-tab-analysis/index.wxml#L168-L185)、[图表参数](../../miniprogram/components/tl-tab-analysis/chart-options.js#L178-L211)、[颜色映射](../../miniprogram/components/tl-tab-analysis/chart-options.js#L45-L70)。建议文字列日期、本期、上期及变化；图表提供摘要及完整数据表，名称和数值不依赖颜色。字号及对比度须实测，不以静态值认定失败。
5. **P2 信息层级**：概览同时包含总额、笔数、日均、月报、结余、比较和家庭数据。[模板](../../miniprogram/components/tl-tab-analysis/index.wxml#L72-L130)。建议优先突出账期、当前方向总额及比较，弱化重复结余，保留有业务价值的明细；具体布局需在真实数据与设备上验证。

## 06 跨页面交互与实施顺序

- 月份箭头、分析筛选、关闭和底栏加号包含图标或可点击 `view`；节点未见完整可访问名称和选中状态。建议依据微信支持的属性补充名称、角色和状态，读屏实测焦点顺序、弹层关闭及焦点返回；不将 Web 属性直接照搬。[明细](../../miniprogram/components/tl-tab-records/index.wxml#L5-L27)、[分析](../../miniprogram/components/tl-tab-analysis/index.wxml#L3-L40)、[底栏](../../miniprogram/components/tl-tabbar/index.wxml#L10-L15)。
- **阶段 A：可信与恢复**：复现分析二次失败、核定月报与 AA 口径、修复访客入口；补状态和语义组合测试。
- **阶段 B：连续任务**：修复两类分页失败反馈、统一公共按钮；确保游标与快照冲突路径安全。
- **阶段 C：可读与精修**：图表文本对照、无障碍标记、预算去重及近似金额；在设备上验证后才调整局部尺寸与层级。
- 建议验收：所有错误能解释并重试；只读用户无写 CTA 且服务端继续拒绝写入；展示/复制语义一致；分页失败不丢已读上下文；图表核心值可从文字获得。
