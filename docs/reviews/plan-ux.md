# 方案候选：安心可理解的账本体验

> 供对比的文字方案，**不是实施指令，也不是已实现或已验收功能**。侧重交互状态、无障碍和数据图表，尽量沿用现有页面与组件，不主张重做视觉风格。依据当前工作区的静态审查；具体问题与代码证据见 [UI/UX 专项审查](./ui-ux-review.md)。当前工作区已有未提交变更，实施前应重新核对代码。

## 一、方向与边界

**关键词：清楚的上下文、可恢复的过程、可朗读的数据。** 保持 OurNest 暖红 `#F0442F`、浅暖背景、卡片和自定义导航；沿用本地图标、语义 Token、公共空态/按钮/弹层及现有底部安全区责任，不引入新的品牌语言、图表库或视觉噱头。信息以文字、数字与结构说明，不单靠颜色传达。

现状依据：页面容器由 `miniprogram/pages/index/index.wxml:1-40` 承载首页、明细及分析；首页已有加载/空/错误分支（`miniprogram/components/tl-tab-home/index.wxml:4-22,106-111`），分析已有趋势明细与分类列表（`miniprogram/components/tl-tab-analysis/index.wxml:168-185,247-295`）。以下为**候选设计和待验证推断**；没有运行设备、读屏、故障或性能测试，不将静态审查推断写成实测结论。

### 状态共同约定

- 首次或切换**不同账本/时间/收支上下文**：标题、筛选立即更新，内容进入 Loading，旧上下文的数值和可点击图表不冒充新结果；成功后进入 Ready 或 Empty，失败进入 Error 并提供重试。
- **同一上下文**后台刷新：可保留旧内容，但显示“正在更新”，暂停可能依赖旧快照的下钻；失败时明确“更新失败，当前展示上次结果”，提供重试及上次结果的范围。若权限撤销、账本切换或上下文不明，则清除旧数据，不得展示旧数据作为当前账本内容。是否允许保留旧数据待安全与产品确认；不允许时统一改用错误态。
- 分页失败不替换首屏：保留已加载内容，在列表尾显示错误和重试；快照不一致单独提示并重新获取第一页，不拼接不同快照。异步结果仅能更新匹配最新请求上下文的页面。
- 所有可见状态文字应可被辅助技术感知，具体微信小程序属性、主动播报机制、焦点返回能力与基础库兼容性须先验证；不能直接把 Web 的 ARIA 代码套到小程序。

## 二、首页：从概览到下一步

**改前**：月份与账本类型切换 → 无账本/空态或预算、收支摘要、最近记录；空态无条件提供“记一笔”（`miniprogram/components/tl-tab-home/index.wxml:7-41,112-204`）。

**改后候选结构**：账本名或账本类型与当前月份 → 本月预算或收支摘要 → 最近记录及“查看全部”；按状态替换内容区，不调整卡片总体层级。账本切换入口补足可访问名称“切换账本，当前……”。摘要显示的金额仍使用原服务口径，不在客户端补算历史账目。

| 情况 | 页面/文案示例 | 操作与转移 |
|---|---|---|
| 首次加载 | 骨架 + 可识别“正在加载账本” | 成功进入对应状态；失败进入错误态 |
| 无账本 | “还没有账本”“创建账本后开始记录” | 创建账本；不展示空的统计卡作真实数据 |
| 有账本但无历史 | “还没有记录” | Owner/成员可“记一笔”；访客提示“你可查看账本，记账需由账本成员完成” |
| 本月无记录但有历史 | “本月暂无记录” | 可查看最近有记录的月份；写入入口依角色显示 |
| 请求失败 | “账本数据加载失败，请检查网络” | “重新加载”；同上下文后台刷新按共同约定处理 |
| Ready | 显示月份、摘要、最近记录范围 | 最近记录进详情或可编辑流程；“全部”进明细 |

这里的“本月无记录”与“无历史”是**新增呈现建议**，实现前核实首页所用服务的 `recordCount`/`totalRecordCount` 语义和历史数据权限（当前映射见 `miniprogram/components/tl-tab-home/index.js:64-112,252-276`）。访客没有写入、导入、导出入口；前端隐藏或解释并不能替代服务端授权。共享账本成员仅能编辑/删除本人记录，Owner 可管理全部，具体入口以服务端返回的记录级权限为准。

## 三、明细与记录详情：保留进度，说明权限

**改前**：明细为月份切换 → 收支筛选与月汇总 → 按日记录；过滤明细显示区间汇总与列表；详情提供交易、家庭记录等信息（`miniprogram/components/tl-tab-records/index.wxml:4-95`；`miniprogram/pages/record-filtered/index.wxml:5-25`；`miniprogram/pages/record-detail/index.wxml:7-80`）。

**改后候选结构**：保留月份和筛选 → 清晰标注当前账本、月份、筛选 → 月汇总 → 分日列表；记录行保留类别、日期、成员、带正负号金额。详情沿用分类/金额/时间 → 交易信息 → 家庭记录 → 备注的顺序，补充对记录不存在、失权及网络故障的可理解反馈，不将所有错误都表述为网络问题；是否有可靠错误码需核实。

| 状态/事件 | 文案与行为候选 |
|---|---|
| 筛选后无匹配 | “本月没有符合条件的收入/支出”，提供“查看全部”；不误称整个账本无记录 |
| 已有历史、本月为空 | “本月暂无记录”，提供“查看最近有记录的月份”；访客不出现可执行的写入口 |
| 第一次加载失败 | “明细加载失败” + “重新加载”，保持所选月份和类型 |
| 追加失败 | 在已有列表尾显示“更多记录加载失败” + “重试加载更多”；继续使用相同游标、筛选和账本 |
| 快照变化 | “记录已更新，正在重新加载”；重取第一页并清晰恢复定位，避免静默混合页面；是否自动刷新或先确认待定 |
| 记录已删除/失权 | 若服务能区分，显示“记录已不存在”或“你已无法查看此记录”，提供返回；未知错误使用中性文案及重试 |

`miniprogram/components/tl-tab-records/index.js:292-317` 与 `miniprogram/pages/record-filtered/index.js:125-145` 是分页错误候选调整点；对应模板分别为 `miniprogram/components/tl-tab-records/index.wxml:44-95` 和 `miniprogram/pages/record-filtered/index.wxml:7-25`。详情涉及 `miniprogram/pages/record-detail/index.js:90-116` 和 `miniprogram/pages/record-detail/index.wxml:7-12`。记录级编辑权限不能仅凭账本是否 readonly 推断，需先核验现有服务及编辑页权限判断。

## 四、分析：先确认统计口径，再看走势

**改前**：周/月/年/自定义与收支切换 → 当前周期概览 → 走势/分类/账户/家庭分项；趋势柱可点击，分类已有文本列表与异常重试（`miniprogram/components/tl-tab-analysis/index.wxml:3-40,71-77,138-185,242-295`）。

**改后候选结构**：①账本、周期和收支方向；②合计、笔数、日均及比较口径；③趋势图 + 明细列表；④分类排行 + 占比；⑤账户、家庭分项。保留已有的图表与可展开文本，不将某一种可视化作为唯一信息入口。

1. **状态恢复**：首次加载骨架；同上下文刷新标注“正在更新”；不同上下文切换不显示旧内容。无论曾否成功，只要请求失败，均出现“分析数据加载失败”和“重新加载”。当前条件与清理逻辑见 `miniprogram/components/tl-tab-analysis/index.wxml:57-69`、`miniprogram/components/tl-tab-analysis/index.js:970-1014`；建议先注入失败复核。图表失败不影响文本列表，单独提供“图表加载失败，重试”。
2. **趋势等价信息**：每期文字至少包含日期/周期、当前收支金额；周对照进一步包含本周、上周及差额，未来日期标“未到日期”，不得呈现为真实零消费。筛选、图表、明细行和下钻保持同一范围、币种与方向。若后端未返回对照原值，先核实契约，不能从柱高反推金额。
3. **分类图**：保留类别名、金额、占比和笔数的文字清单，并通过文字/形状区分，不只靠色点；许多类别时优先完整列表，图中合并“其他”必须提供可查看构成且不与业务“其他分类”混淆。现有实现及交互需验证后再决定是否合并。
4. **口径提示**：展示具体账本、周期边界、当前方向；日均分母、进行中周期、上期比较、分类占比分母与舍入规则以实际接口为准，不能凭视觉推导。自定义结束边界当前筛选明细按“起至……前”显示（`miniprogram/pages/record-filtered/index.js:48-63`），应核对分析标签和下钻是否一致，不擅自将排他结束日期写成包含。
5. **生活月报的两个互斥备选**：A（建议优先验证）仅在月度支出上下文打开，文案写明账本与月份；其他上下文隐藏或提供明确的“切换到月度支出查看月报”，切换须经用户操作。B 保留所有周期和方向，动态称“周报/月报/年报”和“收入/支出”，展示与复制共用一个报告数据模型。当前固定支出标题与动态分析方向的疑点见 `miniprogram/components/tl-tab-analysis/index.wxml:71-83,596-610` 和 `miniprogram/components/tl-tab-analysis/index.js:885-897,1091-1114`。何者符合产品期望、家庭/个人账本标题如何区分均待决。

## 五、无障碍与交互细节

- 月份前后箭头、日明细关闭、底栏加号等纯图标操作补充明确名称；周期、收支切换、展开/收起和不可选状态需向辅助技术暴露状态，且不能只用颜色。相关节点：`miniprogram/components/tl-tab-records/index.wxml:5-27`、`miniprogram/components/tl-tab-analysis/index.wxml:3-27,208-214`、`miniprogram/components/tl-tabbar/index.wxml:10-15`。
- 使用平台可用的语义控件及辅助属性，状态变化有可感知反馈；弹层打开后焦点顺序合理，关闭返回触发处。实际小程序 API 能否表达角色、选中态、主动播报和焦点控制需按基础库版本测试并设降级方案。
- 图标可小但触控区域建议不小于移动平台指导的约 44pt/48dp；微信 rpx 与设备实际像素的换算和命中区域必须真机测量，不能把数值直接当作 rpx。验证文字对比、最大系统字号、横屏及安全区，不预设已通过。
- 本地 `ui-ux-pro-max` 检索 `loading error empty states`、`part-to-whole percentage`、`icon button accessible label`，分别支持明确反馈、文本替代与语义名称；搜索结果的 Web/React 实现不直接用于微信小程序，图形选择仍服从项目业务和真实数据。

## 七、验收建议与待决问题

**验收场景（均待实测）**

1. 无账本、无历史、本月空、有历史及 Ready；Owner、成员、访客分别验证空态、可见操作与服务端权限一致。
2. 首次加载失败、成功后同上下文刷新失败、切换账本/时间后失败、权限撤销；页面无空白死路，不将旧账本数据标为新账本，重试使用明确上下文。
3. 普通明细、筛选明细的第二页失败与重试、快照变化重载、连续快速切换；无重复记录、漏记或不同快照混排。
4. 周/月/年/自定义 × 收入/支出；对照已知测试数据检查区间边界、总额、笔数、日均、占比、上期和下钻；月报展示及复制逐项相符。
5. 微信开发者工具与 iOS/Android 真机分别验证读屏名称、状态和焦点、文字替代、触控范围、动态字号、对比度、图表失败备用、底部安全区及弱网。关键路径通过自动测试与项目要求的 `npm run verify`、`npm run ui:check` 和相关人工回归，实施视觉变更时再按规范运行视觉检查。

**需要用户/产品决定**

- 生活月报选 A 固定月度支出，还是 B 动态周期与方向？访客是否允许复制报告须先确认现有“禁止导出”边界，不预设复制等同允许导出。
- 同上下文刷新失败时展示带时间与上下文的旧结果，还是一律隐藏？权限变化与切换账本必须清除旧结果。
- 快照变化是否立即重载并回到顶部，还是先解释并由用户确认？
- 无历史访客空态提供哪些真正可用的下一步？是否显示账本 Owner 的联系提示取决于隐私政策。
- 各统计口径、零值与未来日期、分类“其他”、日均分母和同比/环比规则需对照云函数契约及产品确认；基础库辅助能力、屏幕朗读与实际触控均需设备验证。
