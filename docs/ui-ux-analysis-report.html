1 视觉设计系统与风格语言 (Design System)

Tokens & Palette

OurNest 整体构建在温暖的“家庭壁炉 / 温润账本 (Warm Hearth & Ink)”语境中。彻底摈弃了泛滥于大众 AI 生成界面的冷色高饱和紫蓝渐变、刺眼霓虹光晕和浮夸毛玻璃，转而采用沉静暖红与米暖灰的搭配，带来亲近且耐看的家庭陪伴感。

📐 4px / 8rpx 弹性栅格

全站间距以 8rpx、16rpx、24rpx、32rpx、48rpx 为基本进阶，严控自由随意像素；内边距与外边距符合“内聚外疏”的群组层级原则。

🔘 嵌套圆角约束 (Nested Radii)

外卡片采用 --tl-radius-card: 34rpx，内部输入框与操作按键为 --tl-radius-control: 20rpx，形成符合光学美感的内外角嵌套关系。

🌑 克制的层次与阴影

除底部导航栏采用防漂浮轻微阴影 (0 -8rpx 24rpx rgba(49,37,34,0.06)) 外，其余卡片主要依赖 1rpx 微边框和浅底色阶表达空间层级。

2 全局功能架构与交互逻辑 (Feature & Flow)

Architecture & UX States

小程序采用“单 Shell 承载 4 大常驻 Tab + 中央微凸快捷记账”的核心框架，结合微信原生胶囊自定义导航栏和安全区，实现高频记账与深度分析的双轨并进。

🎯 4+1 核心导航模式

  • 首页 (Home)： 月度收支大盘、本月结余总览、预算进度水位条与预警、最近收支记录。
  • 明细 (Records)： 按月份归集的流水列表、按日 Sticky 头部聚合（日收/日支）、无缝游标无限加载。
  • 中央 FAB (Record Hub)： 核心记账入口，弹出快捷记账面板或进入全功能记账页，支持多分类、账户、分摊与小算盘计算。
  • 分析 (Analysis)： 周/月/年/自定义/累计 5 大维度看板，集成多维趋势柱状图、月度日历热力、分类环形占比及家庭成员透视。
  • 我的 (Profile)： 多账本管理与切换、家庭协同成员与邀请邀请码、分类自定义、预算设定与账单导入。

🔄 状态机闭环与防白屏机制

  • 互斥状态链： 遵循 Loading (Skeleton) → Error (Retry) / Empty (Action) → Ready，禁止在加载中提前渲染空容器或报错。
  • Tab 保持与懒加载： 采用 visitedTabs 机制，未点击的 Tab 不初始化，已访问的 Tab 在切换时仅隐藏（display: none / hidden class），避免重复请求和图表重绘。
  • 家庭分摊模型： 独创“付款人 (Payer)”与“消费归属人 (Consumer)”解耦机制，支持公共支出、多人平摊与个人独享。

5 UNSLOP 9-Pass 红线审查与去“AI感”优化建议

Redline Audit

依据 UNSLOP 规范审查：“Craft keeps the chrome quiet and puts the richness into one or two moments”。OurNest 整体底子极佳，没有使用 AI 模板常见的全屏紫蓝渐变和浮夸发光，但在图表调色与控制台层级上仍存在一些“AI痕迹”值得精细化打磨。

Pass 1: Spacing & Alignment (间距与对齐) 良好 (Pass)

严格遵循 8rpx/16rpx/24rpx 节奏。卡片内边距统一为 24rpx~34rpx。数字列均实现了 tabular-nums 右对齐，图标与文本垂直居中规范。

Pass 2: Color Semantics (色彩语义与图表调色) 需要重构 (Slop Found)

🚨 严重色彩歧义隐患： 在 chart-options.js 的 categoryChartColor() 中，通过分类字符串哈希随机抽取 CHART_COLORS。这导致支出分类有可能被赋予收入绿 (#25A66A)，收入分类可能被赋予支出红 (#F0442F)！在财务记账场景下，这会给用户带来灾难性的心理误判。
🚨 年度支出柱的“彩虹条”： year-cashflow 中将最大支出染成黄色、最小支出染成蓝色。UNSLOP 明确指出：“No rainbow bars inside one series... One accent per chart”。同一支出序列应保持同色系灰阶或统一红调，不应混杂多种高饱和互补色。

Pass 3 & 4: Copy & Icons (文案克制与图标一致性) 优秀 (Craft)

全站 0 处 emoji 滥用，统一采用本地 Remix Icon 线性图标；标题干脆利落（如“支出构成”、“消费走势”），绝无“超级助手、智能黑科技、AI赋能”等口号式喊话。

Pass 6: Layout & Control Density (控制台布局密度) 建议精简 (Need Polish)

统计页头部纵向堆叠了 4 层操作控件：①周期分段器（周/月/年/自定义/累计）→ ②日期前后翻页器 → ③收支分段器（支出/收入）→ ④二级浮动锚点（小结/分类/账户/家庭）。在普通手机上占用了近 40% 的首屏可视面积。

❌ 现有潜在问题 (Before)
  • 分类颜色哈希随机分配，可能出现“绿色支出扇区”打破认知习惯。
  • 年度收支柱状图中，最高月显示橙黄、最低月显示冷蓝，形成一序列多色杂乱。
  • 统计页头部 4 层控制条同时展开，挤占图表可视高度。
  • 部分过渡动效带有弹性，在低端机型上偶尔出现掉帧感。
✅ UNSLOP 改进建议 (After)
  • 语义锚定调色： 支出分类锁定在暖红-暖橘-土黄-紫灰温暖渐变阶；收入分类锁定在墨绿-薄荷绿阶，绝不互串。
  • 单序列纯化： 年度支出柱全用暖红；极值点通过柱顶徽标或微弱饱和度微调表达，杜绝黄蓝红彩虹条。
  • 头部控件整合： 将二级分段器或辅助日期筛选整合为沉浸式紧凑状态栏，下放空间给核心图表卡片。
  • 硬件加速微动效： 统一使用 180ms ease 线性过渡，禁用大范围 scale，保证滑动如丝顺滑。

6 微信小程序工程约束与设备适配 (Engineering Suite)

WeChat Platform Specifics

📱 胶囊避让与安全区

自定义导航栏使用 wx.getMenuButtonBoundingClientRect() 动态解算胶囊上下间距与标题垂直居中；底部严格应用 constant(safe-area-inset-bottom) 与 env(...) 双重兜底，兼顾新老 iOS 与折叠屏。

⚡ Canvas 2D 内存与手势协同

ECharts 容器在 scroll-view 内部容易产生滚动劫持。当前采用同层渲染 Canvas 2D，并在 chart-controller.js 中实现严格的 disposeAll 机制，Tab 离开或页面卸载时注销图表事件，杜绝内存泄漏。

🌐 游标分页与数据安全

记录分页采用服务端 { date, id } 双键游标，避免高频增删场景下的跳页与重复；云函数作为权限唯一裁决者，绝不轻信客户端传入的角色声明。
